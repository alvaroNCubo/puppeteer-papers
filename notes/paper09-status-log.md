A dependency-evidence pass then replaced the loose "the domain references nothing" with the precise claim the argument needs — the domain declares no dependency on the framework or on any staging (verified: no project or package reference, `dotnet list package` empty, no framework namespace, attribute or interface in its sources) — and states the honest residue: the domain satisfies framework conventions without importing it, including one empty public anchor type that exists so a host can hand over the assembly. §9 accordingly says the contract is provided by the substrate and bound in the staging rather than merely "moved," and answers the objection that a provided mechanism is a port by the test that separates them: the domain compiles and its 44 tests pass with the framework absent from its build graph (Appendix A, Lab E, which now carries the project file verbatim). A methodology pass then separated measurement from argument in Appendix A: the results table carries only measured counts, and the fused and ported baselines those zeros are implicitly set against — which were never built — are stated after it as reasoning, explicitly not as results, with the ported comparison named as the obvious next measurement; §2 and §9 no longer present that comparison as a number. A further correction followed: the earlier comparison misstated ports-and-adapters on the driving side, where the primary port is the domain's own API and no test doubles it, so that side is zero against zero; and a domain needing nothing outward declares no driven port either. §9 now locates the comparison where it actually bites — what a deployment needs *outward* of the domain, namely state that outlives a process and reaches a second machine, which a ported design obtains through a declared dependency and which here is a property of the substrate — and states the residual claim as that history and durability are not among this domain's requirements. The ported baseline was then BUILT and counted (Appendix A, Lab F), which corrected the paper further: an implementation per staging and a stand-in per driven port are confirmed, but a domain edit per staging is REFUTED (a ported rule model takes a new transport at no cost, twice), a stand-in "per side" is refuted, and the build graph TIES — so the unit of account was wrong. A port costs a domain nothing per staging and everything per capability its ports do not carry: cross-process persistence moved the ported arrangement by +204/−9, of which 61 changed lines are in the rule model itself, where the journaled one did not move at all — with the caveat stated in the paper that the larger figure depends on where the ported domain is taken to end, a reader counting only the pure model reading it as +56/−5. Two concessions now run toward the baseline — the build-graph tie, and the journaled domain's framework anchor type, for which the hexagon needs no counterpart — and distribution was measured against no baseline at all. §1, §2, §8, §9 and Lab E revised accordingly. §4 was then demoted from a logical necessity to a consequence of role separation: returning state in a command's response is read-your-writes, a recognized session guarantee (Terry et al., 1994) and not an error; the present IS observable by an audience, as this paper's own polling observer shows; so what survives is the standing distinction — a live read taken in order to act belongs to the party acting — which in that form is Paper 4's and Paper 8's, applied here rather than extended, plus the design corollary that a command's response cannot serve a client that issued none. A graph-vocabulary pass then fixed three things: the domain is a SINK in the dependency graph and the ROOT of its reverse, and the paper now states one orientation at a time instead of mixing sink language with ancestor language in a single breath; a position in a graph individuates nothing, so the measured structural property is no longer presented AS the identity but as evidence about a relation, with the reading kept separate from the measurement; and the subclass analogy is replaced by a library compiled in ignorance of its callers, since a base class does declare an interface for its subclasses and inheritance is the textbook case of strong coupling. §2 then resolved a self-contradiction a reviewer found in it: "no host binds the domain directly" was too strong, since three StageManager hosts name the anchor type to hand the assembly along (reaching it through the actor's transitive reference, without declaring one), and "the `Well` is handed to each as a parameter" was simply wrong — no host constructs or passes a `Well`, which is built inside each node by the actor's recorded seeding act. The declared-reference claim, and the sink/root property that rests on it, are unaffected. §2 then gained a measurable reinforcement one level down, at the members: every verb-bearing type in the domain is `internal` and its whole public surface is the empty anchor, so a staging holds a name and not a handle, not even the actor can invoke a domain operation in the host language, and the framework is the only invoker — the compiler refusing where reflection admits. In-language access had to be granted by name from inside the domain (`domain/AssemblyInfo.cs:8-9`, to the test project and one console host), which is an authored and enumerable exception; that one of the two is a staging is stated rather than glossed, as is the finding that the console no longer exercises its grant, which is left standing and reported rather than removed to buy a cleaner claim. §9 gains the structural counterpart: a port must be visible outside the domain to be implemented there, so a ported domain has at least one externally callable operation per port where this one has none. §7 was then reconciled with Lab B, which contradicted it: three machines keep three journals converging by replication and a catch-up path, so the narrative is in three places and reading it does depend on a mechanism. The claim is restated as being about completeness at a reader rather than physical singularity — the three are copies of one record, each holding the whole game, against a correlating case where each store holds a different fragment and the whole was never anywhere — which makes the honest form "one logical narrative, replicated, with convergence the framework guarantees", weaker than one place and what the labs support; and it is scoped to a single actor's own first-person account, a system of several needing relating this paper does not take up. §3's fact-versus-view line was then made falsifiable, since as written it was not: the emitted set of cells is COMPUTED inside the domain (a union of pile and piece, clipped to the frame), so "raw fact" overstated it and derivation cannot be the criterion, the automated player's column profile being a derivation too. The criterion is now stated as one question a third party can put to the source — does a rule of the domain depend on the notion? — which separates occupancy by position (collision is membership over cells; a complete row is counted in them) from column heights, gaps and bumpiness (named in no operation of the `Well`). Its limit is stated with it: the criterion makes the line auditable, not sharp or permanent, since which notions a domain owns is a modelling judgment and an operation deciding by column height would legitimately move it. Re-decomposition was then MEASURED (Appendix A, Lab G): the `Well` cut into a pile role and a piece role, with 11 of 12 hosts untouched and the 12th needing one line, no divergence over 47,783 steps, and the mechanism confirmed as read-and-re-perform rather than journal surgery.
